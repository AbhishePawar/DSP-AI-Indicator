==================================================
PERMANENT RESPONSIVE DESIGN PRINCIPLE
==================================================

THIS PRINCIPLE MUST APPLY TO ALL CURRENT AND FUTURE DESIGN CHANGES.

The DSP-AI-Indicator website is a multi-device product.

Every new screen, page, component, visualization, interaction, modal,
popup, chart, infographic, form, navigation element, result component,
profile component, settings page, PDF/share interface or future feature
MUST follow the responsive design principles defined below.

Do NOT treat responsive/mobile design as a one-time task.

Whenever any future UI/UX change is made to the product, automatically
consider and implement its:

• Desktop version
• Laptop version
• Tablet version
• Android mobile version
• iPhone mobile version

A change is NOT considered complete if it works only on desktop.

==================================================
GLOBAL DESIGN RULE
==================================================

ONE PRODUCT.
ONE DESIGN SYSTEM.
MULTIPLE SCREEN SIZES.

Desktop, tablet and mobile should feel like the same DSP-AI-Indicator
product while being intelligently adapted to each device.

Never create a desktop-only feature and assume it can simply be
scaled down later.

==================================================
NO "SHRUNK DESKTOP" DESIGN
==================================================

Never solve mobile design by simply:

• Scaling down desktop
• Reducing font size excessively
• Compressing cards
• Shrinking charts
• Squeezing tables
• Removing important information
• Making buttons tiny

Instead:

REFLOW
REORGANIZE
PRIORITIZE
SIMPLIFY

when moving from desktop to mobile.

==================================================
RESPONSIVE PRIORITY
==================================================

Desktop:

More information can be visible simultaneously.

Mobile:

Prioritize the most important information first.

Use progressive disclosure for secondary information.

Example:

Desktop:

Financial Score
+
Supporting metrics
+
Trend
+
Historical comparison

Mobile:

Financial Score
↓
Primary insight
↓
2–4 key metrics
↓
View Details
↓
Additional information

==================================================
TOUCH-FIRST MOBILE DESIGN
==================================================

Every interactive desktop feature must have a touch-friendly mobile
equivalent.

Never rely only on:

Hover
Mouse movement
Right click
Tiny clickable icons

For mobile use:

Tap
Swipe
Scroll
Expand
Collapse
Bottom sheets
Touch-friendly controls

==================================================
FUTURE NAVIGATION CHANGES
==================================================

If new navigation items are added in the future:

Desktop:
Use sidebar/header navigation where appropriate.

Mobile:
Automatically adapt to drawer, bottom navigation, or contextual menu
depending on the function.

Do not allow navigation to become overcrowded on mobile.

==================================================
FUTURE MODALS / POPUPS
==================================================

Desktop:

Centered modal where appropriate.

Mobile:

Use a responsive full-width modal or bottom sheet when more appropriate.

Never allow a desktop modal to simply overflow the mobile screen.

==================================================
FUTURE TABLES
==================================================

Whenever a new table is introduced:

Desktop:
Use full comparison table when appropriate.

Mobile:
Automatically choose between:

• Horizontal scroll
• Stacked cards
• Priority metrics
• Expandable rows

based on readability.

Never compress a complex financial table into unreadable text.

==================================================
FUTURE PDF / SHARE FEATURES
==================================================

Any future:

Download
Share
Export
PDF
Print

feature must work naturally across desktop and mobile.

Mobile sharing should support native mobile sharing where appropriate.

==================================================
ACCESSIBILITY
==================================================

Every future responsive change must preserve:

• Readability
• Sufficient contrast
• Keyboard accessibility on desktop
• Touch accessibility on mobile
• Clear focus states
• Meaningful labels
• Reduced-motion support
• Screen-reader-friendly structure where applicable

Do not rely exclusively on color to communicate financial status.

==================================================

==================================================

• AI reasoning
• Chain-of-thought
• Internal prompts
• System prompts
• AI provider details
• Model details
• Agent architecture
• Research orchestration
• Verification process
• Backend workflow
• Internal scoring calculations
• Internal data pipeline

COMPLEXITY BEHIND THE SCENES.
CLARITY IN FRONT.
