# Concept ID Registry

## Introduction

This registry is the authoritative catalogue of every ontology concept identifier used by DSP AI Indicator under REP-002 Version 1.0.0.

- Every ontology concept must appear in this registry before it is treated as official.
- Concept IDs are immutable once assigned.
- Concept IDs are never reused.
- Deprecated or superseded concepts remain in the registry for historical continuity.
- This registry is the single source of truth for namespace allocation across all ontology books.

Concept definitions live in the ontology books. This registry records identity, status, and version metadata only. It does not redefine meaning.

# Rules

1. Every concept ID is unique across the entire REP-002 namespace.
2. Assigned IDs never change.
3. Assigned IDs are never reused, including after deprecation or archival.
4. IDs are allocated sequentially within each book prefix.
5. The same concept name must not be registered under more than one ID.
6. Cross-book duplicate definitions are prohibited; references must use the owning book ID.
7. A concept is not official until its ID appears in this registry and its definition is approved in the owning book.

---

# Change Control

1. Allocation of a new ID requires an update to this registry in the same change set as the book entry.
2. Concepts that are withdrawn remain in the registry with Status set to Deprecated or Archived and a Notes explanation.
3. Version fields track the ontology concept version, not the software application version.
4. Registry changes must be recorded in `CHANGELOG.md`.
5. The registry is reviewed as part of REP-002 ontology governance before any book advances from Planned to Approved.
